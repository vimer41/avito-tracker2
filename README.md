# Avito Radar

Telegram-бот для отслеживания новых объявлений на Авито. Пользователь присылает ссылку на поиск, бот проверяет её с частотой тарифа и присылает новые лоты в Telegram сразу после их появления в выдаче.

Стек: Python 3.11–3.12, aiogram 3, curl_cffi, SQLite.

---

## Возможности

| Раздел | Описание |
| :--- | :--- |
| Радары | Любая ссылка на поиск Авито. Сортировка по дате включается автоматически; объявления, опубликованные до создания радара, не присылаются. |
| Фильтры | Стоп-слова, обязательные слова, диапазон цены, только с доставкой, без продвинутых объявлений, поиск только в заголовке. |
| Карточка лота | Цена, адрес, продавец, отметка о цене ниже рыночной, кнопки «Открыть на Авито», «Стоп-слово», «Скрыть продавца», шаблон сообщения продавцу. |
| Чёрный список | Скрывает все объявления выбранного продавца. |
| Ночной режим | Выключен по умолчанию. Тихая доставка или отложенная отправка в часы, заданные пользователем (МСК). |
| Пробный период | Выдаётся за подписку на канал проекта. |
| Оплата | Telegram Stars, разовая оплата на 30 дней без автосписания. Возврат через `refundStarPayment`. |
| Напоминания | За 3 дня и за 1 день до конца подписки, за 30 минут до конца пробного периода, а также при окончании доступа. |
| Поддержка | Обращения с текстом, фото, документами и голосовыми; ответ администратора из интерфейса бота. |

## Тарифы

| Тариф | Радаров | Проверка ссылки | Срок |
| :--- | :---: | :---: | :---: |
| Пробный период | 1 | раз в 20 с | 24 часа, бесплатно |
| Базовый | 1 | раз в 40 с | 30 дней |
| Средний | 2 | раз в 30 с | 30 дней |
| Полный | 4 | раз в 20 с | 30 дней |

Актуальные цены — на экране тарифов в боте.

- Тарифы различаются только числом радаров и частотой проверки. Найденный лот отправляется без задержки на всех тарифах.
- Если одну ссылку отслеживают пользователи разных тарифов, она проверяется с частотой самого быстрого из них.
- Оплаченные дни добавляются к текущему сроку. Смена тарифа пересчитывает оставшийся срок.

> [!NOTE]
> Все даты в интерфейсе указаны по московскому времени (МСК).

## Как это работает

```
 Ссылки радаров ──► Планировщик ──► Загрузка страницы ──► Разбор ──► Отбор лотов ──► Очередь ──► Telegram
                   (scan_planner)   (parser, proxy_pool)  (SSR JSON)  (scheduler)    (outbox)
```

1. **Группировка.** Радары с одинаковой нормализованной ссылкой объединяются: одна загрузка страницы обслуживает всех подписчиков.
2. **Планирование.** Каждая ссылка получает срок следующей проверки по самому быстрому тарифу среди её подписчиков, с небольшим случайным разбросом.
3. **Загрузка.** Запрос выполняется через сервер или прокси.
4. **Разбор.** Список объявлений берётся из встроенного в страницу JSON. Если каталога на странице нет, проверка считается неудачной.
5. **Отбор.** Новые лоты проходят фильтры каждого радара и проверку возраста. Один лот приходит пользователю один раз, даже если подошёл нескольким его радарам.
6. **Доставка.** Уведомления записываются в очередь в SQLite и отправляются с учётом ограничений Telegram. Если в одном чате скопилось четыре лота и больше, они уходят одним сообщением-списком.

### Возраст лота и догон

| Ситуация | Какие лоты приходят |
| :--- | :--- |
| Обычная проверка | Не старше лимита радара (по умолчанию 5 минут, максимум 30). |
| Радар снят с паузы | Не старше 10 минут. |
| Ссылка не проверялась дольше лимита (перезапуск, сбой сети) | Не старше 30 минут, не более 10 самых свежих. |
| Доступ возобновлён после окончания подписки | Старые лоты не присылаются: первая проверка только запоминает текущую выдачу. |

Возраст считается от времени публикации, которое указывает Авито. Объявление появляется в поиске после модерации, поэтому обычно приходит через 1–3 минуты после публикации.

## Сеть и прокси

Канал — это один исходящий IP-адрес: сервер или прокси. У каждого канала своё ограничение скорости и учёт ошибок; проблемный канал временно выводится из работы.

| Режим (`NET_MODE`) | Поведение |
| :--- | :--- |
| `direct` | Только IP сервера. |
| `proxy` | Только прокси. Без прокси сканирование приостанавливается. |
| `both` | Прокси и сервер делят нагрузку. |
| `auto` | Прокси при их наличии, иначе сервер. |

Прокси добавляются из панели администратора. Перед добавлением каждый прокси проверяется, дубликаты отбрасываются. Режим сети переключается без перезапуска.

## Установка

### Требования

- Linux-сервер с Python 3.11 или 3.12.
- Токен бота от [@BotFather](https://t.me/BotFather).
- Бот должен быть администратором канала, за подписку на который выдаётся пробный период.

### Запуск

```bash
git clone https://github.com/vimer41/avito-tracker2.git /opt/avito_parser_bot
cd /opt/avito_parser_bot
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env    # заполнить переменные, см. ниже
sudo cp avito-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now avito-bot
```

### Основные переменные `.env`

| Переменная | Назначение |
| :--- | :--- |
| `BOT_TOKEN` | Токен Telegram-бота. |
| `ADMIN_IDS` | Telegram ID администраторов через запятую. |
| `TRIAL_CHANNEL` | Канал для пробного периода, например `@avitoradar1`. |
| `STARS_PAYMENTS_ENABLED` | `1` включает оплату Stars. По умолчанию выключена. |
| `PRICE_RUB_BASIC`, `PRICE_RUB_MEDIUM`, `PRICE_RUB_FULL` | Цены в рублях на экране тарифов. |
| `TARIFF_INTERVAL_LITE`, `TARIFF_INTERVAL_STANDART`, `TARIFF_INTERVAL_PRO` | Частота проверки по тарифам, в секундах. |
| `NET_MODE` | Начальный режим сети; далее меняется из панели. |
| `PROXY_URL` | Один прокси из `.env`, дополнительно к списку в панели. |
| `DB_PATH` | Путь к базе SQLite. По умолчанию `data/bot.db`. |

Полный перечень настроек с значениями по умолчанию — в `config.py`.

## Проверка

### Тесты

```bash
export AVITO_RADAR_TESTING=1
python -B tools/check_syntax.py
python -B tools/run_offline_tests.py                      # весь набор, около 4 минут
python -B tools/run_offline_tests.py tests.test_features  # отдельные модули
```

Тесты работают во временных каталогах, не читают `.env` и не обращаются к сети: внешние запросы заблокированы.

### Непрерывная интеграция

При каждой отправке в репозиторий GitHub Actions прогоняет офлайн-тесты на Python 3.11 и 3.12.

## Структура проекта

```text
bot.py              Точка входа: база, интерфейс, команды, запуск фоновых задач
config.py           Настройки, тарифы, цены
database.py         Схема SQLite, пользователи, радары, очередь уведомлений
ui.py               Эмодзи, кнопки, отрисовка экранов
middlewares.py      Контроль доступа, журнал действий

scan_planner.py     Расписание проверок ссылок
monitoring.py       Воркеры сканирования
parser.py           Загрузка и разбор страниц Авито
collector.py        Сбор страниц каталога
proxy_pool.py       Каналы, ограничение скорости, выбор канала
proxy_check.py      Проверка новых прокси
seen_cache.py       Память уже обработанных лотов
radar_filters.py    Фильтры радара и рыночная цена
scheduler.py        Отбор лотов, формирование и доставка уведомлений

billing.py          Платежи и возвраты Stars
reports.py          Напоминания о подписке, ежедневный отчёт, резервные копии
trial_gate.py       Пробный период за подписку на канал
logger_setup.py     Настройка журналов
log_report.py       Отчёты для отладки и оценки готовности

handlers/           Обработчики Telegram
  common.py         Старт, профиль, тарифы, справка, ночной режим
  searches.py       Радары и их настройки
  payments.py       Оплата Stars
  support.py        Поддержка
  admin.py          Панель администратора

tests/              Офлайн-тесты
tools/              Деплой, проверки, диагностика
```
